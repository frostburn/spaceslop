# Architecture and maintenance

## Entry points and ownership

| Location | Responsibility |
| --- | --- |
| `src/main.ts` | Lightweight sector menu, session entry/exit and update prompt. No renderer or game imports. |
| `src/levels.ts` | Small menu catalog, shared route durations and level IDs; layout modules derive their duration from it. Keep it independent of scene constructors. |
| `src/app/flight-session.ts` | One hangar/run: HUD, preparation, simulation clock, pause/results and context recovery. |
| `src/app/input.ts` | Scoped keyboard and pointer controls. All listeners end with the session's abort signal. |
| `src/app/offline.ts` | Save/check selected level packages without downloading other sectors. |
| `src/game.ts` | Shared deterministic flight/combat simulation; level math remains in the named layout/combat modules. |
| `src/view.ts` | Shared camera, ship, weapons, feedback and warm-up. A view belongs to one level. |
| `src/rendering/level.ts` | Typed level renderer contract: roots, frames, actor models, boss contact, warm-up and disposal. |
| `src/rendering/loaders.ts` | The seven dynamic rendering entry points. |
| `src/rendering/levels/*.ts` | Level-owned scenery, actors, boss posing, texture loading, capture and effects. |
| `src/assets/catalog.ts` | One media path catalog and an explicit list of textures used by each level. |
| `src/encounter-texture.ts` | Optional texture loading, bounded deadlines and safe fallbacks. No enemy imports. |
| `scripts/level-packages.ts` | Build the menu's static dependency closure and each level's offline package. |
| `scripts/check-build.mjs` | Enforce menu budget, package isolation and production exclusions. |

Existing level geometry, rig and layout modules retain their descriptive prefixes (`preserve-*`, `vent-*`, `io-*`, `titan-*`, `ice-*`, `hive-*`, marine/ant helpers). The renderer entry point shows which pieces a stage uses. Shared effects stay separate from simulation geometry. The asset workshop intentionally loads the full model collection and its texture helper; it is a development entry point only.

## Startup and session lifecycle

The initial HTML/CSS and menu contain no WebGL context, game loop, pilot images or level media. Selecting a card changes metadata only. **Prepare flight** imports the session and shared engine, then invokes only the selected level factory. That factory constructs its scenery/actor pools and loads its media. Preflight uploads that level's resources and shared weapons before enabling launch.

A session's abort signal owns controls, focus/media listeners, resize observation, preparation and the animation loop. Returning to the menu cancels them. Each session gets a fresh canvas; disposing an older context cannot accidentally destroy a new renderer on the same canvas. The session abort signal stops pending texture application and Titan slicing. Disposal waits for those preparation promises, releases render targets, geometry, material/texture GPU resources and the context, and clears uploaded image maps on shared materials. JavaScript modules remain in the browser's module cache between visits.

If a module download fails, the menu offers **Reload menu** before retrying; native module-map failures can survive a reconnect in the same page.

Simulation is fixed-step. Presentation time freezes on pause/results. Preserve that distinction when adding animation. `FlightView` rejects a flight from a different level: switching sectors requires a new session rather than mutating a live renderer.

## Level renderer contract

A factory returns a `LevelScene`. Its root contains only that stage's objects. `update(frame)` poses scenery, boss and enemies; `models[index]` identifies the currently visible living model for the corresponding simulation enemy, so laser contact remains correct. `contact` maps boss targets to posed weakpoints. Optional `orientation`, `reveal`, `capture` and `effects` hooks cover stages with special cameras or refraction. `present` replaces the final scene draw for a level-owned lens pass; preflight uses the same hook so its linear-color shader variants and targets warm before launch.

List all actor contact models and warm-up batches, including broken/severed phases and later-wave variants. `prepare` primes stage effects; `afterWarmup` restores temporary priming state. Own any offscreen render target through `dispose`. Do not allocate unbounded geometry, programs or particle pools as waves spawn.

## Assets, cache and deployment

Vite hashes the contents of existing optional media into query versions. Missing files do not generate image requests. A level factory loads its own catalog entries; shared ship armor and the hangar portraits are the common media.

The service worker precaches only the static menu dependency closure, its registration helper and `level-packages.json`. Dynamic imports are deliberately excluded from that traversal. The generated package manifest contains the shared session code plus the selected renderer's static dependency closure and that level's media. Preparing a level caches that package. The menu can check complete code packages without downloading their contents, and its offline-storage control can release all saved level files without clearing the shell or pilot preference. The runtime cache also serves image/script/style requests. Shell readiness and level readiness have different UI wording; the initial menu alone does not imply every stage works offline.

Rebuild after owner art uploads. Test changed media at the same filename to catch stale-cache regressions. Use Vite's base URL throughout; never hard-code `/assets/` or `/encounters/` at runtime. Validate both root and subpath deployments. HTTPS is required for service workers outside localhost. Keep deployment entry files revalidatable and hashed chunks available long enough for existing tabs.

## Adding or changing a stage

1. Add its menu metadata/ID and simulation rules. Keep the menu catalog free of rendering dependencies.
2. Add a renderer factory under `rendering/levels`, register its dynamic loader, and declare its media in the asset catalog.
3. Supply procedural fallbacks, pooled actor/contact mappings and complete warm-up/disposal hooks.
4. Extend the package/build isolation check for a new ID. Check network requests: menu selection must not fetch stage code or pictures; preparation must not fetch another stage's media.
5. Verify stage, approach, boss phases, lasers, restart, pause/resume, cancellation and switching away/back. For loading changes, complete a production offline run with art and a media-free run. Include a portrait viewport and clean console check.

`npm test` covers simulation, geometry, contacts and effects. `npm run build` also checks unused locals/parameters. `npm run test:build` checks delivery boundaries. Browser checks cover actual WebGL, lifecycle and service-worker behavior; a successful TypeScript build alone cannot establish those.

## Orbital preserve scenery

`preserve-flyer.ts` owns the Microraptor flock courses, delayed slot spacing, tangent-derived heading/bank, wing stroke/tuck clock and rotated combat lobes. `preserve-waves.ts` assigns every former scout slot to these flyers while preserving the larger raptor slots and repeated weapon drops. `preserve-flyer-geometry.ts` samples smooth ribcage/keel, neck, pelvis, skull and mandible profiles, cuts paired lined nasal passages into the closed muzzle, recesses the eyes, and builds tapering limb, tail and digit skins. `preserve-flyer-rig.ts` roots smaller mantle feathers on that torso and combines it with the four feather fans, feathered crown and hooked claws, then batches fixed anatomy and shares template geometry across ten scene-owned rigs. The detailed skull receives more geometry while simpler feather longitudinal subdivisions keep each rig below 20,000 triangles and 24 draws. Optional reviewed feather and scale maps only add relief; their absence cannot change flight or combat. The level warms all geometry/material variants before launch and maps living flyers to the same indexed laser-contact models as the other enemies. Routes are absolute and deterministic, so losing a flock leader cannot shift a follower, pause/results freeze both route and wing stroke, and a restart constructs a clean schedule. The workshop exposes an individual wingbeat/swoop cycle and a four-member looping train.

`preserve-lighting.ts` shares the cool-white fluorescent fill and grazing violet UV rim with the workshop. Ceiling-edge tube housings and UV strips live in the station batches, with a light-pink phosphor core, hot-pink middle and fading violet outer halo kept separate from the illumination color. `preserve-fixtures.ts` owns this gradient, fixed empty-socket identities and deterministic ballast stutters. `createPreserveStation` returns its root plus an update driven by the presentation clock; only five existing instance colors change. Two missing tubes retain their channels, pins and mounts. Replay, pause and results never use wall-clock timers for flicker. The broad key retains reduced-strength grounding shadows; crowns, feather instances and service grating do not project fine patterned shadows. The UV rim has no additional shadow map.

`preserve-ambusher.ts` owns the five bank anchors, tracking/locked aim, leap and retreat poses, anatomical flight-plane intersections and swept physical bites. `preserve-ambusher-rig.ts` consumes that pose for the articulated dinosaur, curled tail, warning and splash. The level owns two prewarmed rigs and their shared materials, maps only living anatomy to laser contact, and reuses the reviewed scale texture when present. `preserve-ambusher-geometry.ts` builds smooth torso/skull/mandible lofts, continuous streamed limb skins, curved hand claws and the closed dorsal membrane; the sail profile also supplies thin anatomical contacts at flight height. The tail uses a flattened, vertically expanded streamed cross-section. Hip and shoulder fullness is sculpted into the torso surface. Radius profiles wrap each limb through its joints with muscle bellies, tendons and embedded roots, rather than separate intersecting joint balls. `preserve-ambusher-mouth.ts` owns one lower-jaw tongue, a dark palate, gum ridges, dentition rooted in sampled oral jaw surfaces, and streamed cheek membranes that stretch with the gape. Teeth and their jaw share the same parent transform; fixed anatomy merging must preserve dynamic cheek buffers. Smaller orbital groups contain inset eyes and reusable closed-eye lids; geometry shared with visible joints is already uploaded before a death pose needs it. Hide uses irregular pigment mottles and scale relief, and the sail has small integral rib folds. On defeat, simulation retains the struck pose and start time: a continuous sideways roll lowers it onto the terrain/water while preserving habitat scroll. Corpses have no hitboxes, weapon targets or additional drops, expire within six seconds, and reuse the same two rigs. Pulse retains those harmless falling bodies; approach/restart clears them. Rendering uses the frozen stage clock on results, and the workshop offers separate ambush and defeat timelines. Foliage and rocks leave launch pockets at the same anchors. Submerged anatomy has no floating hitbox; the exposed head/neck accept every weapon. No ambusher state belongs to the menu or survives a flight session.

`preserve-layout.ts` owns deterministic terrain sampling, route extent and the fixed flight frame. `preserve-scenery.ts` composes the world and its broad fluorescent key; `preserve-station.ts`, `preserve-terrain.ts` and `preserve-foliage.ts` own the structure, soil/outcrops and planted layers. `preserve-dock.ts` owns the external entrance, `preserve-water.ts` owns flowing irrigation, pooled whitewater and submerged bed stones; `preserve-water-surface.ts` owns stream/pool depth and current attributes plus the scene-clock water shader, and `preserve-traces.ts` places nesting signs. `preserve-botany.ts` and `preserve-rocks.ts` supply shared procedural silhouettes; `preserve-waves.ts` is the patrol schedule. The 100-second route uses smooth wet/dry/nesting weights rather than swapping backdrops. Water profiles and basin levels also carve the terrain. A radial grid gives pools real interior depth samples, matching the stream’s heightfield-derived bathymetry. Depth controls water tint, absorption and shore alpha; the underlying modeled bed remains visible. Rotated multi-scale noise drives current-aligned normals and broken ceiling glints, with no scene capture or extra image assets. Shore soil darkens near the same water level. Surface geometry and bed instances stay static as only the shared flow clock advances. Soil starts inside the docking mouth, leaving the approach genuinely open to space. Per-bay culling bounds the visible scenery, and only nearby crown batches animate; all resources warm before flight. The grow-light direction stays fixed while `preserve-shadow.ts` snaps a padded shadow window in the narrowed habitat’s metric and keeps the shadow camera up axis registered through rotation. The terrain closes down to the hull at its front and side edges. `rendering/flight-camera.ts` supplies the oblique camera and the same flight-plane projection for laser tracing. Preserve patrol flight is parallel to the habitat; `preserveFrame` moves the 26-degree view tilt into the camera and eases it out as the world turns toward the boss. This keeps z=0 control and collision coordinates fixed while ships and projectiles pass physically under the dock header. Geometry helpers and scene-local materials stay in `preserve-geometry.ts` and `preserve-materials.ts`. The workshop creates the same scenery as the level. It does not load the retired preserve plate. Ground, rooted plant placement and deck structure share world coordinates; optional maps cannot change their geometry or gameplay.

`groundskeeper.ts` owns attack timing, the locked aim contract, two-link arm poses with a shared elbow hinge frame, hand axes, abdomen clearance, claw curves and physical contact and the belly target transform. `groundskeeper-plumage.ts` owns the sparrow-inspired palette, coarse broken breast streaks, back/scapular mottles and feather-shaft/vane-margin pigment. Root colors are sampled once, remain attached through animation, and are independent of the optional reviewed feather grain map. Neck/scalp batches and the scaled face carry the matching countershading, pale eyebrows and dark eye stripes; the camouflage adds no texture request, render pass or animation clock. Rendering consumes that same pose in `groundskeeper-rig.ts`; the muzzle/jaw/eye assembly lives in `groundskeeper-face.ts`, and `groundskeeper-skull.ts` owns the indexed skull, inset nasal passages and surface-rooted scalp feathers and forward eye sockets, with geometry, material and bounded warning/debris helpers kept separate. `preserve-arena.ts` places the circular conservatory in the habitat world. The six-second approach uses `preserveFrame` and `preserveScroll` for the whole world, including the boss. `Flight` owns the attack aim, Pulse interruption and frozen results clock; optional textures cannot affect these. The shared pose also owns restrained chest expansion and weight shift, planted feet and delayed head/hand motion; its chest attachment transform keeps limb roots and belly contacts aligned with the breathing body. Negative pose time is a quiet idle leading continuously through the approach into combat, using the simulation clock so pause/results freeze it and replay scrubbing is repeatable. Neck plumage uses persistent seeded scatter rather than time-dependent randomness. Both arm segments share their elbow plane normal; flattened claws anchor their cross-section to the hand and transport it along the curve; their renderer must not infer roll from the bone direction alone. The arena apron uses disjoint annular sectors above the structural floor; `preserveGround` lowers the habitat soil below that slab inside its footprint. The workshop reuses both the live rig and the full scenery.


## Synthwave boulevard

`boulevard.ts` owns the 100-second route, 20 waves, four hovercar courses, seven-second ascent/camera swing, scenery scroll and pursuit-cruiser timing. The flight plane stays fixed and the camera never follows a winding road. The scenery turns through 74.7 degrees while the ship rises six units relative to the road. `boulevardBossPoint` transforms the same world entrance into the existing `(0, 4.2, -12)` combat target; the road cannot sweep through the player during that move. After the approach, the cruiser and road advance together at reduced speed. Hovercars use the shared compact shot/laser/contact bounds, with a larger armored variant. All four sidearms, sentry, Towline and Pulse work on the boss's permanently exposed cyan core; aimed two-cannon fans lock before firing.

The selected renderer under `rendering/levels/boulevard.ts` owns all scenery, pooled actor models, materials, preflight batches and cleanup. `boulevard-scenery.ts` builds a palm resort, entertainment blocks, two moving monorails and later skyline scenery from instanced modules. `boulevard-venues.ts` composes stepped hotels, fan-marquee clubs and rounded glass atriums, with rooftop pools, lounge furniture, rails and changing tower/spire silhouettes. Window bays now use actual floor slabs, structural jambs, recessed room walls, furniture, transparent glazing, balconies and skylights. Footprints, heights and setbacks vary; pocket courts interrupt the building rows, and monorail supports occupy reserved gaps. The retired façade atlas is neither requested nor cached. `boulevard-layout.ts` shares the intersection and lamp anchors between scenery, road shaders and drainage. At the fountain’s four-way crossing, side streets, curb cuts and four crosswalks replace the uninterrupted promenade; buildings and palms leave both arms clear. The side asphalt shares the road capture and height field, has no overlap with the main surface, and remains registered to the fountain during scrolling. `boulevard-fountain.ts` owns the central court’s tiered basin, animated jets, water normals and one reusable spray batch. Its highest jet remains below combat altitude, and ground cars divert around the basin. `boulevard-arch.ts` sweeps a broad bevelled cross-section into a continuous gate with a polished left shell, a matching violet vector half, panel joints, luminous edge rails and grounded pedestal collars. Its HDR lighting environment is source-built and scene-owned; no extra scene capture is needed. Three early/mid-route gates share geometry/materials, and the final pursuit corridor stays open. Palms stand in the clear promenade strip and grow above each bay’s nearby solid roofs or neon crowns; foliage stays above the roofline instead of intersecting it. Low street furniture stays beneath the combat plane; palm crowns, entrance arches and monorails can pass above it. Late district bays recycle through the ongoing pursuit, without creating resources. `boulevard-rigs.ts` shares geometry/materials across light and armored hovercars and articulates the cruiser's cannons and exposed wing. A child hover frame adds small uncorrelated trim corrections on the presentation clock. Laser anchors ride that frame; the moving core stays well inside the fixed combat proxy. `boulevard-cruiser-geometry.ts` builds its closed chamfered hull, sloped windshield and chrome struts; the exposed wing has a real two-sided lattice cage around its machinery, and the rotary guns have dark bores. `boulevard-geometry.ts` batches fixed anatomy, transforming both endpoints of any vector stroke. `boulevard-vectors.ts` draws chosen contours, architectural rhythms, palm spines/blades/stems and wing spars independently of the solid meshes. Strokes are depth-tested rounded ribbons with consistent screen thickness in both the main view and reflections. The arch weaves long lozenges between its profiles; mountain ridges use sparse contour paths. No surface triangulation is traced. Closed dark back-facing shells sit behind vector buildings, spires, arch ribs and the cruiser’s open wing: they hide distant scenery while preserving the view of interior machinery. The mountain relief stays beyond the visible city through the pursuit.

`boulevard-materials.ts` owns the vector lighting, procedural asphalt fallback and a small reflection-lighting environment. `boulevard-city-lights.ts` derives scene-only material variants with slow cyan/pink/violet gradients and offset, smoothly fading room and street lights. Native geometry/instance positions anchor color and fixture phases before the camera transform; pursuit recycling cannot change them. Actors keep the original materials. One presentation-clock uniform drives these shaders without updating geometry or instance storage. `boulevard-weather.ts` builds a repeatable centimetre-scale road-height field with irregular depressions beneath actual arch gutters, monorail edges and selected atrium canopies. `boulevard-road.ts` displaces a tessellated asphalt mesh and keeps water level across those depressions. One 384×768 half-float planar capture (no MSAA) supplies clear puddle reflections and a weaker, rough reflective water film across visibly grained asphalt. Height gradients and world-registered surface grain distort the film; five capture taps spread its glints along the road. Broad irregular puddles cover roughly two fifths of the road, with extra curb basins beneath the street lamps. Modeled lamp housings contain bright downward-facing cores that appear in the same live reflection capture. Drips fall under gravity from registered sources, then drive up to six short-lived local ripple fields; dry ground clips the ripples. The six-bay relief period agrees with pursuit recycling. Rain uses one prewarmed instance buffer, and its dynamic batch keeps culling disabled after preparation. World positions, pools, trains and all weather use the frozen presentation clock.

`boulevard-glow.ts` retains a sharp linear-color scene (capped at 800×1280, two MSAA samples), filters its highlights through two half-resolution targets, and adds a weak, broad, slightly horizontal diffusion. Ships, bullets and telegraphs keep their original sharp cores; the DOM HUD is unaffected. `boulevard-sun.ts` keeps a circular disk fixed while its horizontal gaps translate upward at 0.07 units/second, with a red/gold vertical gradient and faint warm halo. The lens composite refracts its surroundings with slow rising heat waves, reusing the sharp capture and a depth attachment; both the original and displaced samples must lie behind the heat plane. The disk masks foreground/background ordering between the moving bands, and the shimmer is bounded around its projected ellipse. Offscreen filter passes stay linear and the final composite alone encodes display color. The level releases the lens depth attachment and all lens/reflection targets on exit, including canceled preparations. Lens drawing restores target, viewport and scissor even after a failed capture. Targets resize with the viewport; waves, drips and ripples allocate no new GPU resources. No extra image assets or wall-clock animation are required.

The optional media are `public/encounters/boulevard-asphalt.png` and the existing armor map. Asphalt supplies surface grain, not painted lighting/reflections. `assets/catalog.ts` restricts their loading to the boulevard package. Texture replacement finishes before preflight, and abort/late-image cleanup follows the common texture loader. The previously uploaded façade PNG remains untouched on disk but has no renderer or offline-package dependency. The menu still imports no renderer; the Vite-only workshop has a separate boulevard sector for full-route scrubbing, arch, fountain, hovercar and cruiser inspection. Production excludes the workshop and transition skip.

Enemy projectile dispatch in `FlightView.drawProjectiles` defaults to the shared hostile plasma for every sector. Frostwake and Broodlock opt into their ice/spore styles; new sector IDs do not require an allowlist entry to make enemy fire visible. The Boulevard regression drives patrol and cruiser fire through real instance batches and checks that all sectors select exactly one hostile style.

Boulevard requests a 2.5× `friendlyGlow` gain through the level contract. `rendering/friendly-glow.ts` applies it once per session-owned unlit material in explicitly friendly roots: fighter, drone, wing pods, friendly shots, engines, muzzle flashes, lasers, Towline and Pulse. It leaves hull paint, enemies, scenery and other sectors at their own lighting values. Shader gain is inserted before display encoding and warmed before launch.
